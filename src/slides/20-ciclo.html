El ciclo completo

Del usuario al sistema externo y de vuelta. MCP cubre un tramo concreto: el que va del client al server. Los extremos son tu aplicación y el modelo.

Resultado contenido tipado
El modelo decide. El host le pasa una lista de tools; el modelo elige una. Este paso ocurre dentro del host y no genera tráfico MCP.
El host aprueba. La política de permisos —por ejecución, por tool o por sesión de trabajo— es de la aplicación, no del protocolo.
El server ejecuta. Valida argumentos, habla con el sistema externo y devuelve contenido. El resultado vuelve al contexto y el ciclo se repite.

MCP cubre solo Client ↔ Server. Todo lo que hay a la izquierda y a la derecha es tu arquitectura.

Esta slide cierra el acto del flujo. Si la audiencia se lleva una sola imagen, que sea esta: el protocolo no empieza en el usuario ni termina en la respuesta del modelo. Empieza cuando el host ya decidió qué exponer y termina cuando el server devuelve el resultado.

Los dos flags son las fronteras de seguridad. La decisión del modelo no es una decisión de negocio; la aprobación del host es la que convierte una intención en una acción permitida.

Si el host no pide permiso, MCP sigue funcionando: el protocolo no lo exige. Pero la responsabilidad de lo que se ejecuta es de la aplicación que conectó el server.
