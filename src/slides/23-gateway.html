MCP y API Gateway

No compiten. El gateway protege y enruta el backend; el server MCP describe capacidades al modelo. En una arquitectura madura, cada uno hace su trabajo.

El gateway no entiende el schema de una tool; el MCP server no reemplaza WAF, cuotas ni routing.

API GatewayHTTP

Autentica y autoriza en el borde, aplica cuotas, WAF, TLS, routing y telemetría. No sabe qué es una tool ni qué argumentos acepta.

MCP ServerSemántica

Publica tools y resources, valida argumentos, aplica permisos por tool y traduce la llamada a la API. No reemplaza el gateway.

Cómo convivenJuntos

Gateway delante del MCP server para OAuth y límites; MCP server delante del gateway para semántica. Cada capa valida lo que entiende.

La confusión típica: “¿MCP reemplaza mi API Gateway?”. No. El gateway es una capa de control de tráfico HTTP; MCP es una capa de descripción de capacidades para un modelo.

El gateway sigue siendo necesario para OAuth, cuotas, WAF, mTLS, enrutamiento y observabilidad. El server MCP añade una cosa que el gateway no tiene: un contrato machine-readable de qué puede hacer el modelo y con qué schema.

Ojo con el término “MCP gateway”: a veces se usa para un agregador de servers MCP (multiplexa conexiones y credenciales). Es otra pieza, no un API Gateway. En esta slide hablamos del gateway HTTP de toda la vida.
