Resources — la aplicación decide qué incluir

Un resource es una fuente de datos de solo lectura con URI única y MIME type. No ejecuta nada: informa. La aplicación decide si lo incluye en el context window.

La aplicación decide Solo lectura URI + MIME

Resources · datos

Archivos, esquemas de base de datos, documentación o respuestas de API. Cada resource tiene una URI única y declara su MIME type para que el host sepa cómo tratarlo.

Puede ser un resource directo o una plantilla con parámetros. La aplicación elige qué traer, cómo filtrarlo y cuánto pasarle al modelo.

resources/list resources/templates/list resources/read subscriptions/listen
file:///Documents/passport.pdf Resource directo · application/pdf · el host decide si lo lee
calendar://my-calendar/June-2024 Resource directo · disponibilidad del calendario
travel://activities/{city}/{category} Plantilla · se instancia con barcelona/museums

LA DIFERENCIA CON TOOLS

Un resource no ejecuta: informa. Si necesitas una acción con efectos, es una tool. Si necesitas contexto, es un resource.

La aplicación puede incluir un resource automáticamente, sugerirlo o dejar que el usuario lo elija. El protocolo no impone una UI de selección.

Resources es la primitiva más “aburrida” y, para muchos casos, la más útil: dar contexto de calidad sin que el modelo tenga que pedirlo. La diferencia con tools es de control: aquí decide la aplicación, no el modelo.

La URI no es un detalle cosmético: es la identidad del dato. Permite listar, leer, cachear y suscribirse a cambios. Las plantillas permiten describir familias enteras de datos sin enumerarlas.

Si la audiencia pregunta por RAG: resources no es RAG. Es el canal por el que el host obtiene datos; cómo los selecciona o indexa es cosa suya.
