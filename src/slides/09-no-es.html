Acto 2 · La definición

Qué NO es MCP

La mitad de la confusión desaparece cuando se delimita el contrato. MCP no es la inteligencia, ni el agente, ni la aplicación: es la capa que las conecta.

01

No es un modelo

No entrena, no infiere y no reemplaza al LLM. Es el cable entre el modelo y el resto del mundo.

02

No es un agente

No decide objetivos ni planea pasos. Define cómo se exponen y se invocan capacidades.

03

No es un framework

No impone arquitectura, UI ni ciclo de vida de la app. Los SDKs son conveniencia, no el protocolo.

04

No reemplaza tu API

Tu API sigue existiendo. MCP la describe para que un modelo pueda descubrirla y usarla.

05

No dicta el contexto

No decide qué entra en el context window ni cómo se gestiona. Eso es responsabilidad del host.

S2 · Architecture overview · alcance explícito

“MCP focuses solely on the protocol for context exchange—it does not dictate how AI applications use LLMs or manage the provided context.”

MCP se centra únicamente en el protocolo para el intercambio de contexto: no dicta cómo las aplicaciones de IA usan los LLM ni cómo gestionan el contexto que reciben.

→ MCP es una capa de contrato. Lo que construyas por encima —el agente, la UI, la política de contexto— es tu diseño, no el del protocolo.

Esta slide evita tres discusiones típicas: “¿MCP es un agente?”, “¿es un framework?”, “¿reemplaza a mi API?”. La respuesta corta a las tres es no. La respuesta útil es: MCP define el contrato de intercambio de contexto, nada más.

La cita de la arquitectura es la más importante del deck: MCP no dicta cómo la aplicación usa el LLM ni gestiona el contexto. Eso deja fuera decisiones de producto que mucha gente atribuye al protocolo.

Si la audiencia es de plataforma, remarca el punto 04: MCP es una capa de descripción encima de lo que ya tienes, no un sustituto de tu API o de tu gateway.
