Acto 1 · El problema

Qué sabe y qué no sabe un LLM

El modelo no está roto: está aislado. Todo lo que sabe del mundo está dentro de una ventana que se abre en cada llamada y se cierra cuando termina.

SÍ

Lo que sí hace

Dentro del context window

01

Predice el siguiente token, uno a uno. Todo lo demás —razonar, resumir, escribir código— se apoya en esa operación.

02

Razona sobre lo que ya está en el contexto: tu prompt, el historial, los documentos y los resultados que la aplicación le pasa.

03

Sigue instrucciones y emite JSON estructurado, incluido un tool call con nombre y argumentos.

context window · todo lo que el modelo puede ver en esta llamada

NO

Lo que no hace

Fuera del context window

01

No sabe nada posterior a su corte de entrenamiento. El mundo cambió y sus pesos no.

02

No ejecuta código, no consulta una base de datos, no llama a tu API. Solo produce texto —o una intención de llamada— que otra pieza debe ejecutar.

03

No conoce tus sistemas, tus permisos ni tus datos privados. Si no están en el contexto, no existen para él.

El corte de entrenamiento y la falta de acceso no son un bug del modelo: son su condición de funcionamiento.

→ MCP no hace al modelo más listo. Le abre puertos hacia lo que ya existe fuera de la ventana: datos, tools y workflows.

Este es el encuadre que hace clic: el LLM es una función pura sobre su contexto. No tiene efectos secundarios. No puede consultar nada. Si quieres que use el clima de Barcelona de hoy, alguien tiene que meterlo en el contexto.

El problema no es la inteligencia; es el aislamiento. MCP no cambia el modelo, cambia lo que el host puede poner a su disposición.

Ojo con la frase “el modelo no ejecuta nada”: es literal. En la slide 04 se ve por qué function calling tampoco lo cambia.
