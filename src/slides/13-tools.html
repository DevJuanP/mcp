Tools — el modelo decide, el host aprueba, el server ejecuta

Una tool es una función con contrato: nombre, descripción, inputSchema y efectos. El modelo la elige; el server la ejecuta; el host decide si pide permiso.

El modelo decide Con efectos Consentimiento

Tools · acciones

Funciones que el modelo puede invocar. Pueden escribir en una base de datos, llamar a una API, modificar archivos o disparar lógica. Tienen efectos, y por eso el host puede exigir aprobación.

Cada tool declara un inputSchema en JSON Schema. El server valida los argumentos y devuelve contenido tipado.

El protocolo no impone la UI de aprobación: el host puede mostrar un diálogo por ejecución, preaprobar operaciones seguras o registrar actividad. La decisión es del host.

{
  "name": "weather_current",
  "title": "Weather Information",
  "description": "Get current weather information for any location worldwide",
  "inputSchema": {
    "type": "object",
    "properties": {
      "location": {
        "type": "string",
        "description": "City name, address, or coordinates"
      },
      "units": {
        "type": "string",
        "enum": ["metric", "imperial", "kelvin"],
        "default": "metric"
      }
    },
    "required": ["location"]
  }
}

El modelo ve nombre, descripción y schema. No ve tu implementación. La descripción es parte del contrato: un schema perfecto con una descripción mala produce malas llamadas.

Tools es la primitiva que la gente suele confundir con “MCP entero”. No lo es: es una de las tres. La característica definitoria es que las controla el modelo: él decide cuándo llamar, con qué argumentos, y puede encadenar varias.

El consentimiento no es un detalle de UI: es la frontera de seguridad. Una tool puede borrar un archivo o enviar un mensaje. El protocolo permite que el host muestre la llamada, la apruebe o la bloquee antes de que salga.

Remarca que inputSchema es JSON Schema: la validación es real, no una sugerencia en prosa.
