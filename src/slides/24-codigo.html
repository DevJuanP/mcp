El código — un server mínimo, real

El quickstart oficial de TypeScript, recortado. Lo importante no es memorizarlo: es ver dónde vive el contrato y dónde empieza tu implementación.

src/index.ts@modelcontextprotocol/server
import { McpServer } from "@modelcontextprotocol/server";
import { serveStdio } from "@modelcontextprotocol/server/stdio";
import { z } from "zod";

// serveStdio llama a esta factory cada vez que necesita una instancia
function createServer() {
  const server = new McpServer({
    name: "weather",
    version: "1.0.0",
  });

  server.registerTool(
    "get_alerts",
    {
      description: "Get weather alerts for a state",
      inputSchema: z.object({
        state: z.string().length(2).describe("Two-letter state code"),
      }),
    },
    async ({ state }) => {
      const text = await fetchAlerts(state); // tu implementación
      return { content: [{ type: "text", text }] };
    },
  );

  return server;
}

serveStdio(createServer, {
  onerror: (error) => console.error("Weather error:", error),
});

Recortado del quickstart oficial. El handler real consulta la API del NWS; aquí se sustituye por fetchAlerts para que quepa.

McpServer

Instancia aislada. serveStdio llama a la factory cada vez que necesita un server.

registerTool

El contrato. Nombre, description e inputSchema. Zod genera el JSON Schema que verá el modelo.

handler

Tu código. Recibe argumentos validados y devuelve content[]; los errores de negocio van como contenido.

serveStdio

La negociación. Atiende server/discover y mantiene compatibilidad con clients 2025.

stderr

La regla de oro. Nunca console.log: stdout es el canal JSON-RPC. Usa console.error.

Ojo: server.connect(new StdioServerTransport()) compila, pero solo sirve a clients legacy. Para hablar 2026-07-28 y 2025, usa serveStdio.

Este código es real y está recortado del quickstart. La fábrica createServer no es un capricho: serveStdio la llama para cada instancia, incluida una sonda de server/discover que se descarta si el client cae a initialize.

La parte que más se olvida: en stdio, un console.log escribe en el mismo canal que los mensajes JSON-RPC y rompe el server. Todos los ejemplos oficiales insisten en console.error.

La distinción entre error de negocio y error de protocolo también importa: si la API externa falla, normalmente devuelves contenido con el error para que el modelo lo lea. Si la llamada está mal formada, devuelves un error JSON-RPC.
