Tres primitivas, tres controles

La diferencia no está en el formato de la respuesta: está en quién decide que la primitiva se use. Modelo, aplicación y usuario tienen cada uno su palanca.

Primitiva Quién controla Qué es Cuándo se usa Métodos
Tools Modelo Acciones con efectos secundarios: escribir, enviar, reservar, desplegar. Cuando el modelo debe decidir y ejecutar algo que cambia el mundo. tools/list · tools/call
Resources Aplicación Datos de solo lectura con URI y MIME type: archivos, esquemas, documentos. Cuando el host necesita contexto y decide qué parte cargar. resources/list · resources/read
Prompts Usuario Plantillas de mensajes con argumentos para una tarea concreta. Cuando el usuario invoca un workflow de forma explícita. prompts/list · prompts/get
EL MISMO VIAJE, LAS TRES PRIMITIVAS Barcelona · 5 días

Prompt · el usuario arranca

/plan-vacation con destination y days. El server devuelve la plantilla y el host la mete en el contexto.

Resource · la app carga contexto

travel://barcelona/forecast y el calendario. El host decide incluir el clima y los museos abiertos; el server solo los sirve.

Tool · el modelo actúa

book_restaurant con fecha y personas. El modelo la elige; el host pide aprobación antes de escribir la reserva.

? La pregunta correcta no es «¿qué primitiva es?» sino «¿quién debe decidir cuándo se usa?». Si la respuesta es el usuario, es un prompt; si es la app, un resource; si es el modelo, una tool.

Esta slide es la tabla de decisión que la gente se lleva. Tools, resources y prompts no son tres sabores de lo mismo: son tres contratos de control distintos.

El ejemplo de Barcelona enseña cómo conviven. El usuario invoca el prompt, la aplicación carga los resources que considera relevantes y el modelo decide si necesita una tool para reservar. Ninguna primitiva reemplaza a las otras.

Si alguien pregunta “¿puedo hacer todo con tools?”, la respuesta es sí, pero pierdes la semántica: el modelo tendría que pedir datos con una tool de lectura y el usuario no tendría un punto de entrada explícito. Funciona; no es el diseño.
