La pila de capas

MCP separa qué significan los mensajes de cómo viajan los bytes. La capa de datos es el contrato; la de transporte es la tubería. Cambiar de tubería no cambia el contrato.

La clave

El mismo JSON funciona sobre cualquier transporte.

La capa de datos define el sobre JSON-RPC, el descubrimiento y las primitivas. La capa de transporte solo mueve bytes, enmarca mensajes y gestiona la conexión.

Servermisma semántica
  • Data layer: JSON-RPC 2.0, descubrimiento, primitivas y notificaciones.
  • Transport layer: establecimiento de conexión, framing y auth.
  • Regla práctica: si cambias el transporte, el payload no se toca.
! El transporte no cambia la semántica. Si un mensaje funciona en stdio, el mismo mensaje funciona en Streamable HTTP.

Esta separación es la que permite que el mismo server funcione local y remoto. La capa de datos no sabe si los bytes van por una pipe o por un POST HTTP.

Para la audiencia de microservicios, la analogía es clara: es como separar el contrato (Protobuf, JSON Schema) del transporte (gRPC, HTTP). El contrato sobrevive al transporte.
