Acto 5 · El flujo real

Stateless — la sesión ya no existe

2026-07-28 elimina el handshake y las sesiones. Cada request lleva la versión y las capacidades que el server necesita. Si un tutorial te muestra initialize, es de otra era.

Antes · ≤ 2025-11-25 Legacy
initialize → initialized → Mcp-Session-Id → requests

El server recordaba versión, capacidades e identidad para toda la conexión o sesión. El primer mensaje condicionaba todos los siguientes.

Ahora · 2026-07-28 Modern
request + _meta → result

Cada request se procesa de forma independiente. La conexión no es una conversación: puedes intercalar requests no relacionados en el mismo transporte.

Qué se eliminó Qué lo reemplaza
Handshake _meta obligatorio en cada request.
Sesiones Sin Mcp-Session-Id; handles explícitos como argumentos.
Requests del server MRTR: resultType: "input_required" y reintento.
Subscribe / GET SSE subscriptions/listen con un stream por request.
Ping y logLevel global ping eliminado; logLevel por request.
Cómo detectar docs viejas Red flag

Si ves initialize, notifications/initialized o Mcp-Session-Id, el documento describe 2025 o antes: ya no aplica.

! Stateless no significa que tu app no tenga estado. Significa que el protocolo no lo guarda por ti: si una operación necesita contexto entre llamadas, el client pasa un handle explícito en cada request.

Este es el cambio que más rompe material existente. La gente aprendió MCP con el handshake y las sesiones; en 2026-07-28 eso desapareció. La versión no subió a 2026-08-01 ni a v2: sigue el formato de fecha y la revisión es 2026-07-28.

Por qué importa en producción: un server stateless se puede reiniciar, escalar horizontalmente y balancear sin sticky sessions. Cada request es autosuficiente. La contrapartida es que el estado de negocio debe viajar explícito.

La nota de Mcp-Session-Id es literal: ya no existe en el transporte. Si lo ves en un client o en un proxy, está hablando la versión anterior.

El matiz de compatibilidad: un server dual-era puede atender clients modernos y legacy. serveStdio lo hace por ti; el código manual con StdioServerTransport se queda solo en legacy.
