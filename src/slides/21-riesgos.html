Acto 6 · Seguridad y cierre

Los riesgos reales

MCP conecta un modelo con sistemas que tienen efectos. Eso crea una superficie de ataque nueva. Estos cuatro vectores están documentados en la guía oficial de seguridad.

01

Prompt injection desde el output de una tool

El resultado de una tool es entrada no confiable. Un documento, una issue o una página web pueden contener instrucciones que el modelo termine siguiendo. No hace falta un usuario malicioso: basta un dato envenenado.

Mitigación Trata el output como untrusted, aplica least privilege y pide aprobación humana antes de acciones sensibles. No pongas secretos en el contexto.
02

Confused deputy

Un proxy MCP con más permisos que el client es engañado para actuar en nombre de otro. El server confía en el proxy y el proxy no verifica quién pidió qué.

Mitigación Consentimiento por client, tokens con audiencia y scope, y credenciales separadas. No reutilices el token de un client para otro.
03

Token passthrough

El server acepta el token del client y lo reenvía tal cual a una API upstream. El token no fue emitido para esa API: su audiencia no coincide y el upstream no puede distinguir al usuario final.

Mitigación Nunca reenvíes el token del client. Haz token exchange o usa credenciales propias del server con el scope mínimo necesario.
04

Servers locales que ejecutan código

Instalar un server local es ejecutar un binario con tus permisos. Puede leer archivos, abrir red y escribir en disco. La cadena de suministro forma parte del modelo de amenaza.

Mitigación Instala solo de fuentes confiables, revisa el código, ejecuta en sandbox o contenedor y limita paths y red con allowlists.
! MCP no es una capa de seguridad. Es un contrato de mensajes: la autenticación, la autorización, el aislamiento y la observabilidad se diseñan alrededor, no vienen incluidos.

No vendas MCP como seguro por diseño. El protocolo define cómo se descubren y se invocan capacidades; no decide qué puede hacer un usuario ni qué datos puede ver.

Prompt injection es el vector que más cambia con MCP porque el modelo recibe output de sistemas externos. La mitigación no es “un mejor prompt”: es limitar privilegios y exigir aprobación en acciones con efectos.

Confused deputy y token passthrough son problemas de arquitectura de auth, no de JSON-RPC. Si tu server es un proxy, la pregunta clave es “¿en nombre de quién actúo y con qué token?”.

El cuarto vector es el menos protocolario y el más real para usuarios de desktop: instalar un server es instalar software.
